# Normalizer Service Fix Prompt

## Problem Summary
The normalizer service has three critical issues preventing schedules from being generated successfully:

### Issue #1: Empty Availability Array Causes Infeasibility
**Current Behavior:**
- When there are no `WorkerAvailability` records in the database for a schedule horizon, the normalizer returns `"availability": []`
- The solver interprets this as "no availability data provided" and may assume nurses are unavailable
- This causes infeasible schedules even when capacity exists

**Expected Behavior:**
- If NO availability records exist in the database for the horizon, the normalizer should log a warning and return an empty array (correct)
- BUT the solver should interpret "no restrictions" as "available for all shifts" (this is a downstream issue, but document it)
- Alternatively, if availability is completely empty, generate default availability rows for all workers covering all dates/shifts as "UNRESTRICTED"

**Fix Location:**
- `src/core/normalizer/normalizer.service.ts` → `buildAvailability()` method (lines ~556-585)

**Implementation:**
```typescript
// If no explicit availability records exist, log a warning
if (rows.length === 0) {
  this.logger.warn(
    `No availability records found for unit ${unitId} between ${startDate} and ${endDate}. ` +
    `Solver will assume all workers are available for all shifts unless explicitly restricted.`
  );
}
```

### Issue #2: Nurse Code Mismatch in Exemption List
**Current Behavior:**
- Constraint profile has `"shiftTypeLimitExemptNurses": ["NURSE_001"]`
- Actual nurse codes in normalizer output are `"001"`, `"002"`, etc. (from `worker_code` field)
- The exemption list never matches because `NURSE_001` is not a valid nurse code
- Result: Shift type limits apply to all nurses when they should apply to none (or specific ones)

**Expected Behavior:**
- Exemption codes should match the actual nurse codes in the payload
- If DB has `"NURSE_001"` but normalizer generates `"001"`, they should either:
  - Match (normalize one to the other), OR
  - Be documented clearly for users

**Fix Location:**
- `src/core/normalizer/normalizer.service.ts` → `resolveConstraintProfile()` method (lines ~437-556)

**Implementation:**
1. Move nurse code generation (lines ~130-160) BEFORE constraint profile resolution
2. Pass nurse code mappings to `resolveConstraintProfile()` as parameter
3. In `resolveConstraintProfile()`, normalize exempt nurse codes:
```typescript
// If we have nurse mappings, normalize exemption codes
if (nurseMappings && exemptNurses?.length > 0) {
  const normalized: string[] = [];
  for (const code of exemptNurses) {
    // Check if already valid
    if (nurseMappings.workerIdByNurseCode[code]) {
      normalized.push(code);
    } else {
      // Try stripping "NURSE_" prefix
      const stripped = code.replace(/^NURSE_/i, '');
      if (stripped !== code && nurseMappings.workerIdByNurseCode[stripped]) {
        normalized.push(stripped);
        this.logger.debug(`Normalized exempt nurse "${code}" → "${stripped}"`);
      } else {
        this.logger.warn(`Exempt nurse code "${code}" not found in unit`);
      }
    }
  }
  exemptNurses = normalized;
}
```

### Issue #3: Contradictory Constraint Logic
**Current Behavior:**
- `forbidEveningToNight: false` (allow Afternoon→Night transitions)
- `evening_to_night_penalty: 99999` (heavily penalize Afternoon→Night transitions)
- These are contradictory—solver doesn't know whether to allow or forbid

**Expected Behavior:**
- Either set penalty to 0 (allow) OR set `forbidEveningToNight: true` (hard forbid)
- Document that `forbidEveningToNight` and penalty should be consistent

**Fix Location:**
- Database: `constraint_profile` table, constraint profile ID 22
- User should fix this manually in the UI/database, OR
- Add validation to `resolveConstraintProfile()`:
```typescript
if (!constraints.forbidEveningToNight && constraints.penaltyWeightJson?.evening_to_night_penalty > 1000) {
  this.logger.warn(
    `Constraint profile has contradictory settings: forbidEveningToNight=false ` +
    `but evening_to_night_penalty=${constraints.penaltyWeightJson.evening_to_night_penalty}. ` +
    `Either forbid (true) or allow with lower penalty.`
  );
}
```
